# 简写生产与项目外 LLM 扩写

本模式的交付物是完整叙事简写和可独立使用的扩写包。全书 3,800 章，规划正文约 1,600 万汉字；正文在项目外由人组织，可使用其他项目或 LLM。本项目不替外部执行结果作完成承诺。

## 字数与预算

每章扩写验收范围 4,000～5,000 汉字。全书预算精确分配为每章 4,210 或 4,211 汉字，合计 16,000,000。个别章节更改预算应同时调整其他章节，不能默认全书每章都写到 5,000 字。

汉字计数包含 CJK 基本区、扩展 A 与补充扩展区，不含标点、数字、英文、空白或 Markdown。简写正文参考每章 900～1,400 汉字，不设固定最短字数，不以固定扩写倍数作为充分性证明。场景、事件、动机和状态字段必须完整；目录式稿件的信息缺失和扩写不足由专用逻辑审查阻断，不能用长度乘法替代。

每章包括 2～6 个场景。各场景预算之和必须等于章节预算，且注明通过哪些动作、交锋、信息发现和转折支撑篇幅。

可读简写由同一份事件链确定性生成，保留动作、作者因果依据、结果、对话意图、情绪和场景交接。模型不再另写一份容易与场景卡不一致的叙事文本；扩写时仍需区分作者知情与人物知情。

全部已提交事件保存在数据库中。具名角色自动建立首次出现、最近出现和原始介绍索引；生成时查询相关人物的状态、首次介绍和较早的出场事件，不仅依赖最近四章。未具名群体留在场景中，不把不同地点的“村民”或“守卫”登记为同一个全书人物。长线约束和伏笔窗口保留，远期各卷的整段细则按当前章节范围选择，减少重复上下文。

## 生成与质检

沿用本书现有十个大阶段及 3,800 章结局，不将通用方案中示例性的“38 卷”套到本书。

1. 使用 Bible 和专用主线里程碑规划临近十章。
2. 检查规划编号、完整覆盖、预算、重复事件及主线节点；规划与当章简写合并做独立逻辑审查，避免后面章节的规划返工阻塞前面尚未生成的正文。
3. 根据已提交前章、相关人物状态和近三十章伏笔活动生成叙事简写与场景卡。
4. 代码检查事件引用、覆盖、场景预算、时间顺序、状态前值与证据。
5. 独立 LLM 审查当章规划和简写的设定、因果、知识、连续性、覆盖、伏笔、扩写充分性和章节边界；不是跳过规划语义检查。
6. 对明确问题自动修复，默认最多两轮；必要时仅重规划当前未提交章节一次，共享该章原有总请求和时间预算。失败保留诊断，不转人工质检，不推进依赖章节。
7. 在一个 SQLite 事务内提交章节、评审和状态变化，再导出扩写包。

简写生产不调用原正文模式的文学总分、正文润色或 10,000 字补足门。原正文模式仍可使用，两个模式的数据和完成状态分开。

章节预算、场景分配和状态提交前值由程序计算。模型只给场景相对篇幅权重，程序分配每场至少300汉字并精确满足全章预算；篇幅容量仍由语义审查核验。原始模型响应保留用于审计，避免错误的数字合计触发全文重写。语义审查读取实际前章状态，继续阻断与历史事实不符的叙事或状态后值。

质检必须指出问题位置、证据及最小修复要求。没有文采、缺少修辞或没有展开全文对话，不能单独作为退回理由。事件编号覆盖不能替代语义覆盖：审查还需确认实际叙事包含对应信息。

正式章节使用第二版证据合同：审查逐个对照规划事件与实际事件，并逐个核对当章里程碑；不能仅返回八项通过。模型选择事件编号并给出对照理由，程序绑定真实动作原句及源任务，避免模型改写引文或抄错哈希造成机械重试。程序不改变审查的通过/失败判断。失败审查即使证据格式有问题，其已明确的问题也用于修复，不通过反复重评挑选通过结果。

第三版合同进一步要求逐场景的绝对日程。模型只提供起止时段、距前场景的天数与本场持续天数；程序计算场景起止日和章末日，处理跨夜、明确的满月/年龄下限及回忆场景。岁按365日、月按30日作内部时序估算，不新增世界历法设定。章末天数不再由模型把章节号直接填入；提交时再次检查与前章的连续性。

`config/condensed_milestones.json` 保留原图全部 49 个节点编号和依赖，修正乱码及与明确 Bible 禁令冲突的表达。N026、N031、N040、N047 的旧日期存在前置依赖或卷区间倒置，分别调整至 989、1423、2601、3401，并记录原因。原图不改。第 918 章保留不完整线索窗口，第 988 章正式取得传承；初期不得传授呼吸法，神魂锚定遵守世界规则。

## 启动

在本技能包目录，使用已安装项目依赖的 Python。现有 `config/llm_providers.json` 决定模型与环境变量；无需另存密钥。

```bash
PYTHONPATH=src python -m novel_engine.condensed run --output /workspace/novel-condensed-3800 --end 3
PYTHONPATH=src python -m novel_engine.condensed run --output /workspace/novel-condensed-3800 --end 3800
PYTHONPATH=src python -m novel_engine.condensed status --output /workspace/novel-condensed-3800
PYTHONPATH=src python -m novel_engine.condensed verify --output /workspace/novel-condensed-3800
```

同一个输出目录自动从首个未提交章节继续。放置 `输出目录/STOP` 可在下一章开始前停止；删除该文件再运行即可继续。失败命令返回非零退出码，不能把进程结束误判为全书完成。

输出目录由调用者显式指定，建议放在源码目录之外。`novel_engine.generate_condensed_chapter(..., output_root=...)` 和 `novel_engine.condensed_status(output_root=...)` 提供异步 Agent API。安装本包后也可使用 `novel-condensed` 命令。

## 外部扩写包

每章目录为 `expansion/chapter_0001/`，包括：

- 使用说明、全书相关规则、人物设定、文风指南和主线里程碑。
- 章节简写、场景卡、前章事件、人物状态及伏笔上下文。
- 完整的扩写提示词、验收提示词和修订提示词，必要资料已内嵌。
- 可选事实变更清单模板。
- 文件哈希、来源章节哈希、前章哈希、设定版本与预算。

直接提交 `扩写提示词.md` 即可，不需要本项目数据库、代码、API或专用插件。模型必须具备容纳完整资料的上下文容量。作者未来知情不等于角色知情，提示词明确禁止提前泄露或执行后章情节。

外部扩写需保留固定事件、信息边界和结束状态，可以自由组织语言、非关键动作和环境细节。发现核心缺失或矛盾时列出问题，不自行补造关键设定。字数需由外部工具统计，不能依赖模型自报。

包内提供独立的 `count_han.py`，只需 Python3 标准库：`python count_han.py 正文.txt --target 4211`。它仅统计传入的纯正文，4,000～5,000 汉字返回成功，越界返回非零退出码；不要把验收说明或事实变更清单混进正文文件。共享版将脚本放在 `shared/`。当前文风依据现有 Bible，尚无用户确认的扩写样文；清单明确记录这一状态，不将文风一致性宣称为已验收。

```bash
PYTHONPATH=src python -m novel_engine.condensed export --output /workspace/novel-condensed-3800
PYTHONPATH=src python -m novel_engine.condensed archive --output /workspace/novel-condensed-3800 --archive /workspace/expansion-packages.zip
PYTHONPATH=src python -m novel_engine.condensed archive --output /workspace/novel-condensed-3800 --compact --from-chapter 1 --end 100 --archive /workspace/expansion-0001-0100.zip
PYTHONPATH=src python -m novel_engine.condensed compile --output /workspace/novel-condensed-3800
```

归档只包含已提交且校验通过的扩写包，不包含密钥、运行数据库或日志。事实变更回流是可选交接格式，不是本项目生产或外部使用的前置依赖。自动读取并合并外部成稿尚不属于此接口，不能自动把变更清单当作已批准设定。

默认归档保留逐章完整提示词；`--compact` 使用批量共享版，设定、文风、里程碑在 ZIP 内只保存一次，逐章提示词明确引用包内 `shared/` 文件。外部项目需先加载这些共享文件，全部依赖都在 ZIP 内。`--from-chapter` 与 `--end` 支持按卷或每百章打包；根交付清单记录实际章节数及请求范围是否齐全，所有文件在归档完成后再次核验。

`compile` 输出已提交章节的简写合订本、章节索引和实际交付数量；部分合订本明确标记未完成，不能冒充全书。

## 恢复、审计与完成标准

SQLite 是正式提交依据，导出文件可由已提交记录恢复。内容哈希与前章哈希构成连续链。重复运行已提交章节不再调用模型；导出失败后可重建，不重写章节。

每项规划或章节操作默认共享 16 次真实请求、900 秒活动时间预算。传输重试和空响应重试同样计费；重启不重置已耗请求和时间，停机时长不计入活动时间。每轮候选稿、问题、评审、原始响应和 usage 保留在输出目录。模型不负责计算或准确抄写 SHA：同步请求与响应由程序绑定，模型回显值保留用于诊断。

发现已经提交的简写存在缺陷时，可使用 `invalidate --from-chapter N --reason ...` 归档原数据库与扩写包，撤销该章及后续依赖，并恢复前缀状态；原请求和费用记录保留。只有明确指定原因时，`extend-budget --operation chapter_N --extra-calls N --extra-seconds N --reason ...` 才会增加恢复额度，每项操作最多额外16次请求、1800秒。额度增加有记录，不重置已耗用量，不自动无限续费。

提示词合同修正后，可在原总请求和时间预算内重新验证候选稿，历史不清空。若需要更新设定，仅当尚无正式章节、生产预算未变时可明确使用 `--refresh-uncommitted-canon`；会保存旧身份记录并撤销未提交的规划，保留全部费用预算。已经提交章节后，修改设定或预算需要显式迁移或新项目，默认拒绝混用。

每份评审最多额外补全一次技术格式，保留候选稿和已有真实问题，仍共享原请求与时间预算；不为缺少证据字段重写正文。在相同合同、上下文和文本下，已经被有效判失败的稿件不能靠再次评审取得通过，必须实际修复或重新规划。

`status.json` 区分正式简写数、已校验导出数、扩写预算、真实请求数、返回 token 和未返回 usage 的请求。未知费用不能当作零；没有价格配置时不虚报货币成本。全书只有在 3,800 章全部正式提交、扩写包全部生成、连续链与全部文件最终校验通过后才标为 `complete=true`。外部成稿始终另标 `external_expansion_verified=false`，不会与简写完成混淆。

本模式降低正文润色和反复全文重写的支出，不保证某个固定节省比例，也不保证外部模型无误。应通过连续真实生成和代表章节的外部试扩写分别验证生产稳定性与扩写适用性。
